Keep the screen open when the subtitles are ready at once

An ask for an audiobook that SubRead did before is done in less than a
second, because SubRead keeps what it transcribed. The screen opened and
closed at once. In Hoshi Reader this looked like a fault: the user
pressed Make and was back in Hoshi before anything was readable.

When the job is done in less than 3 seconds, the screen now stays, says
that the work was there from an earlier job, and has a button that
returns to the calling app. The answer is the same RESULT_OK. A job
that ran for longer still returns by itself.

AlignIntentTest asks a second time for the same files and checks this.
