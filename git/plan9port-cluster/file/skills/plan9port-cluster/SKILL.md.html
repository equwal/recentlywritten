6 # plan9port cluster (p9c)
7 
8 One storage node serves a 9P file tree. Agents put inputs in `/share`, run
9 the heavy command on the node, and write the result back to `/share`. Other
10 agents read it from there.
11 
12 | Part | Where |
13 |---|---|
14 | Storage node | `$P9C_HOST` (SSH login, see "This setup" at the end if present) |
15 | File server | plan9port fossil on `tcp!127.0.0.1!5640` on the node, backed by venti; data in `~/plan9` there |
16 | Writable tree | `/share` (world-writable; every agent uses it) |
17 | Client | `p9c` in `~/.local/bin` on the node: plan9port's `9p` aimed at the server |
18 | CPU | the storage node; check `uptime` before a heavy job |
19 
20 The server listens on 127.0.0.1 only and has authentication off. SSH is the
21 access control: never open port 5640 to a network.
22 
23 ## Use it
24 
25 On the node:
26 
27 ```sh
28 p9c ls -l /share
29 p9c create /share/in.txt              # create an empty file
30 p9c write /share/in.txt <in.txt
31 p9c read /share/in.txt >copy.txt
32 p9c rm /share/in.txt
33 ```
34 
35 From another machine with SSH to the node (the server is only on the node's
36 loopback). A non-interactive SSH shell may not have `~/.local/bin` in
37 `PATH`, so each line adds it:
38 
39 ```sh
40 ssh "$P9C_HOST" 'PATH=$PATH:~/.local/bin; p9c create /share/in.bin; p9c write /share/in.bin' <in.bin
41 ssh "$P9C_HOST" 'PATH=$PATH:~/.local/bin; p9c read /share/in.bin | xz -9 -T0 | (p9c create /share/out.xz; p9c write /share/out.xz)'
42 ssh "$P9C_HOST" 'PATH=$PATH:~/.local/bin; p9c read /share/out.xz' >out.xz
43 ```
44 
45 The second line is the CPU-offload pattern: the input comes from `/share`,
46 the work runs on the node, and the result goes back to `/share`.
47 
48 On Windows, PowerShell has no `<` redirection and adds CRLF to piped text:
49 run these lines through `cmd /c "..."`.
50 
51 ## Set up a node
52 
53 1. Install plan9port. Build fossil with `patches/fossil-remove-uaf.diff`
54    (stock fossil crashes when a client removes a file).
55 2. Copy `bin/p9c-server` and `bin/p9c` to `~/.local/bin`.
56 3. Run `P9C_FOSSIL=/path/to/patched/fossil p9c-server` under a supervisor
57    (runit: `service/runit/run`; replace USER, put it in `/etc/sv/p9c-server`,
58    link it into the service directory).
59    The first start formats `~/plan9` (arena size `P9C_ARENAS`, default 4G).
60 
61 ## Check that it works
62 
63 On the node, in a clone of github.com/equwal/plan9port-cluster:
64 
65 ```sh
66 P9C=~/.local/bin/p9c sh tests/roundtrip.sh   # prints PASS
67 ```
68 
69 ## Mount it (Linux, optional)
70 
71 As root on the node, the kernel 9P client mounts the tree (fossil speaks
72 plain 9P2000):
73 
74 ```sh
75 modprobe 9p
76 mount -t 9p -o trans=tcp,port=5640,version=9p2000,aname=main/active,uname=$USER,access=any 127.0.0.1 /mnt/p9c
77 ```
78 
79 A server restart breaks the mount: unmount and mount again.
80 
81 ## Gotchas
82 
83 - `p9c create` fails if the file exists; `p9c write` then overwrites it.
84 - If `p9c` says "Connection refused", the server is down: restart it.
85 - fossil archives to venti daily at 04:00 and keeps an hourly snapshot.
