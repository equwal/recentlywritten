Windows installer: stop the old bm-watch at an upgrade

The installer starts sbm-setup with the PATH of Windows. That PATH does
not have the Cygwin tools. So "sbm-setup stop" did not find tr, found
no bm-watch, and stopped nothing. After an upgrade, two bm-watch
processes ran. On a new install, "sbm-setup data" did not find mkdir
and cp.

sbm-setup now puts /usr/bin at the start of the PATH.

The installer ran the installed sbm-setup of the earlier version before
it changed the files. The sbm-setup of sbm 0.4 to 0.6 has the problem.
So the installer now installs its own sbm-setup first, and runs it.
