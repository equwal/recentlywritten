Do not show old status texts over the new book

- The user picks a large file A that is no PDF, then B. B shows first.
  Then A failed, and the strip said "This file is not a PDF, or it is
  damaged." over the good book B.
- A restore of the last book that failed after an open of the user
  said its error over the book of the user.
- The SubRead result text of book A ("15 cues, language en, ...")
  stayed in the menu when book B opened.

openBook now ends each failed attempt in one place, and says its error
only when failureShows (book-open.ts) allows it: no later attempt shows
a book, and for the restore, the user started no open after it. An
empty file is now an attempt too, so its error follows the same rule.
When a book opens, the make status goes unless a SubRead job runs or
waits for this book (keepMakeStatus, book-subtitles.ts). The status of
a job that runs stays, because it tells why the button is off.
