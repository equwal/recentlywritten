Offer a SubRead result for a closed book when that book opens

A SubRead result for a book that was no longer open went straight into
the subtitles of that book: makeSubtitles when the book changed while
it read the result file, and checkPendingSubtitles when the book
changed while it waited for the plugin. The result then skipped the
confirm, and the checks of the language and the match rate, which
exist because SubRead 0.9.1 gave "km" and a match rate of 1 for audio
with no speech.

The result now waits in the meta data of its book as a pending result
(BookMeta.subread, a KeptResult with the .srt, the cues, the language
and the match rate), not as its subtitles. When the book opens,
applyMeta offers it with offerSubreadSubtitles, the same confirm and
checks as for the open book, and removes it. makeSubtitles also reads
the result file when another book opened during the job, so that the
result keeps what SubRead told about it for the checks. Before, that
path left only the .srt in the result file, and a SubRead older than
0.10 lost the result.
