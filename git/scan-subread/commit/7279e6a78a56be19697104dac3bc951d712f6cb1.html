Keep the open book when a file does not load

A damaged file in the PDF field broke the open book: the handler closed
the old document before the new one loaded. After the error, Next
changed the page label but not the page, and pdf.js logged "Cannot read
properties of null (reading 'sendWithPromise')". openBook now loads the
new document first. The old book goes only after the load succeeds.

- A file that pdf.js cannot open gives "This file is not a PDF, or it
  is damaged." in place of the InvalidPDFException text.
- A picked file of 0 bytes, for example a file that another app still
  writes, gives "The file is empty or not ready. Try again in a
  moment." for the PDF and for the subtitles.
- decodeSubtitles reads the subtitle file (UTF-8, UTF-16 or Shift_JIS)
  in place of file.text().
- A subtitle file with no cues keeps the cues that are loaded. On the
  phone a PDF in the subtitles field replaced 15 cues with 0.
- The subtitles field has no type filter. A browser download of an .srt
  often has the type application/octet-stream, and the filter made it
  grey in the Android picker.
- Both fields forget the picked file, so the same file can be picked
  again.
- The .srt row shows only for subtitles that SubRead made.
- When all pages are read and less than 30% of the cues match, the
  strip says "These subtitles do not match this book or the OCR
  language." after the count.
- A render of a closed document no longer gives an unhandled
  rejection.

+/**
