Stop the app crash when Android cannot start an activity

startActivityForResult and startActivity throw SecurityException or
ActivityNotFoundException, for example for an audio Uri whose read grant
is gone after a restart, or for a dictionary that the user removed.
Capacitor gave the exception to its plugin thread as a RuntimeException,
and the app crashed.

The helper startForResult catches the RuntimeException and gives it to
the caller, which ends the call:

- lookup: the chosen dictionary falls back to the chooser. When the
  chooser cannot open, the call rejects.
- makeSubtitles: { error: 'cannot_start: <message>' }. The write grant
  of the result file is revoked.
- ankiAdd: { error: 'cannot_start' }.
- pickAudio and openOverlay: the call rejects. shareText already caught
  the exception.

A start that fails gives no result, so the return watch has nothing to
end. subread.ts tells the new error values.
