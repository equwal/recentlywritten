Let a book that the user opens win over the restore of the last book

restoreLastBook did not know about the opens of the user:

- The last book L is large, and the user picks a small PDF B while L
  loads. B shows first, and its copy replaces L. Then the open of L
  gives false, and the restore read that as "the copy cannot be read":
  clearLastBook deleted the copy, which was the copy of B now.
- On the slow first start (the database upgrade), the start card shows
  after 2 s, and the user picks B. The database opens while B loads.
  state.pdf is still null, so the restore opened L as a later attempt,
  and L won over the pick of the user.

Opens now counts the opens of the user (byUser). The restore notes the
count when it starts, and userOpened tells when the user started an
open after that. Then the restore does not open L, and does not forget
the copy. clearLastBook(key) also deletes the copy only while it is of
the book `key`, in one transaction.
