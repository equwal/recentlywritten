Give the start of OCR a time limit

A download of the language data that stalls, for example behind the
login page of a public Wi-Fi, does not end by itself. The page time
limit did not cover the start, so await ocr.start() in readPage waited
for ever: the strip kept "Reading 0/40 · page 1" and showed no Retry.

createOcrJob (ocr-job.ts) now gives the start a time limit,
START_LIMIT_MS, the same 120 s as a page. After the limit the start
rejects with OcrStartError, each page gets that error, and the strip
shows "OCR could not start" with Retry. The job gives the start an
AbortSignal. It aborts the signal at the limit and when the job stops
during a start. createOcr (ocr.ts) then fails the start and stops the
Web Worker that it kept. A worker that starts after the limit stops.
