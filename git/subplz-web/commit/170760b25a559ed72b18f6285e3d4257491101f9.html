Do not answer 500 when the server cannot read the Google Play key

On Python 3.11, Path.is_file raises PermissionError when the service user cannot open the folder of the key. Then settings.play_configured raised, and GET /api/captions answered 500 to each Subrep user. The GitHub build also lost its Stripe packs. POST /api/captions/play-purchase answered 500, and each hourly housekeeping pass failed.

Use os.path.isfile, which gives False for each error. Also make sure that the service user can read the key. An unreadable key now stops only the Play sales, and the server does not sell Play hours that it cannot check.

The README now tells the operator to let subplz open /etc/subplz-web, and to check play_available after the restart.

+    def is_file_on_python_3_11(self, *args, **kwargs):
+        if str(self) == key:

+        return is_file(self, *args, **kwargs)
