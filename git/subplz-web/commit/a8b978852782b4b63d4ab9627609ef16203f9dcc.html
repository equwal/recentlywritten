Fix mkv mux: map streams explicitly, not -map 0

An MP4 stores chapters as a bin_data track, and Matroska accepts only audio,
video and subtitle streams - so -map 0 made ffmpeg refuse the whole file with
"Only audio, video, and subtitles are supported for Matroska". Map v/a/s
explicitly; chapters still carry over through -map_chapters, being container
metadata rather than a stream.
