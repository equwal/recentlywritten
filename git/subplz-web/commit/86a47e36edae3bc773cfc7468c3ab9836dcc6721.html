Put paid and free server jobs on separate queues

A burst worker must take paid jobs only, so that a free credit never
starts a machine that costs money. With the Redis queue, a paid job now
goes to subplz-jobs-paid and a free job to subplz-jobs. billing.is_paid
tells them apart: a bought credit, a book of a monthly plan and an
unlimited plan pay; a free credit, the daily credit and a browser job do
not. worker.py takes the queues in SUBPLZ_WEB_WORKER_QUEUES, paid jobs
first by default.

With Redis, a restart of the web server no longer puts running jobs back
on the queue. A worker on another machine can still run them, and a
second copy would convert the book twice. The in-process queue keeps the
old behaviour, because its jobs stop with the process.

The dev requirements add rq, redis and fakeredis for the queue tests,
and hypothesis for the property tests of the next commits.
