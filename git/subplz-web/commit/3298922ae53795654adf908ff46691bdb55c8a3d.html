Custom cover image for the video, gated behind sign-in

Drop a jpg/png alongside the audiobook and it becomes the video background
instead of the epub's own cover or a plain card.

Signed-in only, and said so before anyone picks a file rather than after:
the drop zone carries "sign in required", the client refuses to attach the
image and explains why, and the server repeats the refusal in
cover_requires_sign_in as a backstop. A visitor who is not signed in still
gets their free book - only the cover is withheld - and nobody waits through
a render to discover the feature was not available.

Account.signed_in is email-based, so it flips on as soon as real auth exists.
