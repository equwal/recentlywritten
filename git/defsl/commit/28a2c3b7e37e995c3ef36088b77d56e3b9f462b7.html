Rewrite defsl as a thin macro over a resolver function

The old defsl never worked. Its COND compared fresh lists with EQL, and
DEFEQUIVS read two package names as one (package symbol) pair. With FiveAM
loaded, the system did not load: "The function SWANK::SLYNK is undefined".

Now the macro only parses its arguments. RESOLVE makes the choice when the
expansion runs. It takes the first candidate whose package exists, whose
symbol exists, and whose symbol satisfies the bound-predicate. The old code
accepted the predicate and ignored it.

- The alias is the symbol that the caller writes, so it goes in the
  package of the caller. The old code interned the name of the fork's
  symbol in *PACKAGE* at load time.
- The lookup uses FIND-SYMBOL on strings. It interns nothing, and the
  reader needs none of the packages.
- EVAL-WHEN defines the alias at compile time, so a file can use an alias
  of a macro that it defines.
- A spec with a package and no symbol is an error at macroexpansion.
- The expansion binds no variable, so the hygiene claim is now true.

Delete utils.lisp and the Alexandria dependency. Nothing uses them.

Add the sl/test system (FiveAM). It tests each subset of three fixture
forks, and these real forks: SLYNK/SWANK/MICROS, SB-MD5/MD5, Eos/FiveAM,
and cl-utilities/Alexandria. Run it with (asdf:test-system :sl).
