92 <span class="a">+#+TITLE: eForth</span>
93 <span class="a">+#+AUTHOR: Spenser Truex</span>
94 <span class="a">+#+EMAIL: web@spensertruex.com</span>
95 <span class="a">+</span>
96 <span class="a">+**** Version 0.0.1</span>
97 <span class="a">+</span>
98 <span class="a">+This is an implementation of an elisp-based FORTH. This means that elisp</span>
99 <span class="a">+is used to write the function definitions. In fact, no FORTH function</span>
100 <span class="a">+definitions are provided at all to the eForth macro from the library.</span>
101 <span class="a">+The main benefit comes from reducing the verbosity of elisp in a small</span>
102 <span class="a">+Domain Specific Language the programmer defines.</span>
103 <span class="a">+</span>
104 <span class="a">+* How? Forth code is</span>
105 <span class="a">+gone through by the pointer moving through the call stack. When a</span>
106 <span class="a">+non-function is found, it is added to the argument stack. When a</span>
107 <span class="a">+function is found, it uses up the argument stack if it has arguments, or</span>
108 <span class="a">+just runs if it is nullary. Nothing else is provided by the</span>
109 <span class="a">+implementation. # Why? Needing to simulate a long set of keypresses to</span>
110 <span class="a">+create an eight panel frame (37 in total), the best option seemeed to be</span>
111 <span class="a">+obviously to create a miniature language with 1 or 2 letter</span>
112 <span class="a">+abbreviations for each. Any arguments to a function can be passed before</span>
113 <span class="a">+it in the list, and there is no need to define a return stack. # Usage:</span>
114 <span class="a">+example:</span>
115 <span class="a">+</span>
116 <span class="a">+#+BEGIN_SRC emacs-lisp :tangle no</span>
117 <span class="a">+(require &#x27;eforth)</span>
118 <span class="a">+(defun 8pan ()</span>
119 <span class="a">+  (interactive)</span>
120 <span class="a">+  (eforth &#x27;((n . (lambda () (switch-to-buffer nil)))</span>
121 <span class="a">+            (d . split-window-below)</span>
122 <span class="a">+            (r . split-window-right)</span>
123 <span class="a">+            (wr . windmove-right)</span>
124 <span class="a">+            (wl . windmove-left)</span>
125 <span class="a">+            (wd . windmove-down)</span>
126 <span class="a">+            (wu . windmove-up)</span>
127 <span class="a">+            (del . delete-other-windows)</span>
128 <span class="a">+            (cf . make-frame-command)</span>
129 <span class="a">+            (nf . other-frame))</span>
130 <span class="a">+          (cf del r r wr wr r d wr d wl wl d wl d wr n</span>
131 <span class="a">+              wr n wr n wl wl wl wd n wr n wr n wr n wl wl wl wu nf)))</span>
132 <span class="a">+#+END_SRC</span>
133 <span class="a">+</span>
134 <span class="a">+=M-x 8pan= will produce a new frame with eight panels (emacs-speak:</span>
135 <span class="a">+&quot;windows&quot;). Here is how it works:</span>
136 <span class="a">+</span>
137 <span class="a">+=eforth= is called with two arguments: the environment, name to function</span>
138 <span class="a">+bindings, and the eforth code list. You can see in this example that</span>
139 <span class="a">+there are no arguments used, since all of these are nullary functions.</span>
140 <span class="a">+Here is how you might use arguments:</span>
141 <span class="a">+</span>
142 <span class="a">+#+BEGIN_SRC emacs-lisp :tangle no</span>
143 <span class="a">+(eforth &#x27;((ff . find-file)) (&quot;~/some-file&quot; ff))</span>
144 <span class="a">+#+END_SRC</span>
145 <span class="a">+</span>
146 <span class="a">+Here we ran =(find-file &quot;~/some-file&quot;)=. If you need to reuse a forth,</span>
147 <span class="a">+just define an =*env*= variable:</span>
148 <span class="a">+</span>
149 <span class="a">+#+BEGIN_SRC emacs-lisp :tangle no</span>
150 <span class="a">+(defvar *env* &#x27;((&gt;r . to-return-stack) ...))</span>
151 <span class="a">+(eforth *env* (forth code here ...))</span>
152 <span class="a">+#+END_SRC</span>
153 <span class="a">+</span>
154 <span class="a">+* Benefits</span>
155 <span class="a">+** Concise code.</span>
156 <span class="a">+Elisp&#x27;s convention of names like:</span>
157 <span class="a">+#+BEGIN_SRC emacs-lisp :tangle yes</span>
158 <span class="a">+org--insert-structure-template-unique-keys</span>
159 <span class="a">+#+END_SRC</span>
160 <span class="a">+(a real function in the org mode) result in extremely verbose code. Using short,</span>
161 <span class="a">+lexical names can reduce code size by a large portion.</span>
162 <span class="a">+#+BEGIN_SRC emacs-lisp :tangle yes</span>
163 <span class="a">+</span>
164 <span class="a">+#+END_SRC</span>
165 <span class="a">+** Compiles to Elisp.</span>
166 <span class="a">+Elisp is hated by many, and for good reason. It is an outdated and clunky lisp.</span>
167 <span class="a">+Many have tried and failed to port Emacs to Common Lisp, without success. Forth,</span>
168 <span class="a">+unlike modern lisps, is designed to be easy to implement. Writing a forth</span>
169 <span class="a">+compiler is in fact a trivial exercise.</span>
170 <span class="a">+</span>
171 <span class="a">+* Drawbacks</span>
172 <span class="a">+** Elispers might not want to read your eFORTH code</span>
173 <span class="a">+** Isn&#x27;t verbose code self-documenting?</span>
174 <span class="a">+NO. Documented code is documented. Using short names with the bindings handily</span>
175 <span class="a">+available in the same form is equally explicit as writing them out every time.</span></pre>
