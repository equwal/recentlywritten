95 <span class="a">+HOW DOES A FORTH WORK?</span>
96 <span class="a">+</span>
97 <span class="a">+</span>
98 <span class="a">+Forth code is gone through by the pointer moving through the call stack.</span>
99 <span class="a">+When a non-function is found, it is added to the argument stack. When a</span>
100 <span class="a">+function is found, it uses up the argument stack if it has arguments, or</span>
101 <span class="a">+just runs if it is nullary. Nothing else is provided by the</span>
102 <span class="a">+implementation.</span>
103 <span class="a">+</span>
104 <span class="a">+</span>
105 <span class="a">+</span>
106 <span class="a">+WHY?</span>
107 <span class="a">+</span>
108 <span class="a">+</span>
109 <span class="a">+Needing to simulate a long set of keypresses to create an eight panel</span>
110 <span class="a">+frame (37 in total), the best option seemeed to be obviously to create a</span>
111 <span class="a">+miniature language with 1 or 2 letter abbreviations for each. Any</span>
112 <span class="a">+arguments to a function can be passed before it in the list, and there</span>
113 <span class="a">+is no need to define a return stack.</span>
114 <span class="a">+</span>
115 <span class="a">+</span>
116 <span class="a">+</span>
