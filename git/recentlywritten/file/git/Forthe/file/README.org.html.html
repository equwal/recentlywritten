24 <a id="l15" href="#l15">15</a> This is an implementation of an elisp-based FORTH. This means that elisp
25 <a id="l16" href="#l16">16</a> is used to write the function definitions. In fact, no FORTH function
26 <a id="l17" href="#l17">17</a> definitions are provided at all to the Forthe macro from the library.
27 <a id="l18" href="#l18">18</a> The main benefit comes from reducing the verbosity of elisp in a small
28 <a id="l19" href="#l19">19</a> Domain Specific Language the programmer defines.

48 <a id="l39" href="#l39">39</a> * How does a FORTH work?
49 <a id="l40" href="#l40">40</a> Forth code is gone through by the pointer moving through the call stack. When a
50 <a id="l41" href="#l41">41</a> non-function is found, it is added to the argument stack. When a function is
51 <a id="l42" href="#l42">42</a> found, it uses up the argument stack if it has arguments, or just runs if it is
52 <a id="l43" href="#l43">43</a> nullary. Nothing else is provided by the implementation.
53 <a id="l44" href="#l44">44</a> * Why?
54 <a id="l45" href="#l45">45</a> Needing to simulate a long set of keypresses to create an eight panel frame (37
55 <a id="l46" href="#l46">46</a> in total), the best option seemeed to be obviously to create a miniature
56 <a id="l47" href="#l47">47</a> language with 1 or 2 letter abbreviations for each. Any arguments to a function
57 <a id="l48" href="#l48">48</a> can be passed before it in the list, and there is no need to define a return
58 <a id="l49" href="#l49">49</a> stack.
59 <a id="l50" href="#l50">50</a> 
60 <a id="l51" href="#l51">51</a> =M-x 8pan= will produce a new frame with eight panels (emacs-speak:
61 <a id="l52" href="#l52">52</a> &quot;windows&quot;). Here is how it works:
62 <a id="l53" href="#l53">53</a> 
63 <a id="l54" href="#l54">54</a> =forthe= is called with two arguments: the environment, name to function
64 <a id="l55" href="#l55">55</a> bindings, and the Forthe code list. You can see in this example that
65 <a id="l56" href="#l56">56</a> there are no arguments used, since all of these are nullary functions.
66 <a id="l57" href="#l57">57</a> Here is how you might use arguments:

80 <a id="l71" href="#l71">71</a> * Benefits
81 <a id="l72" href="#l72">72</a> ** Concise code.
82 <a id="l73" href="#l73">73</a> Elisp&#x27;s convention of names like:
83 <a id="l74" href="#l74">74</a> #+BEGIN_SRC emacs-lisp :tangle no
84 <a id="l75" href="#l75">75</a> org--insert-structure-template-unique-keys
85 <a id="l76" href="#l76">76</a> #+END_SRC
86 <a id="l77" href="#l77">77</a> (a real function in the org mode) result in extremely verbose code. Using short,
87 <a id="l78" href="#l78">78</a> lexical names can reduce code size by a large portion.
88 <a id="l79" href="#l79">79</a> ** Compiles to Elisp.
89 <a id="l80" href="#l80">80</a> Elisp is hated by many, and for good reason. It is an outdated and clunky lisp.
90 <a id="l81" href="#l81">81</a> Many have tried and failed to port Emacs to Common Lisp, without success. Forth,
91 <a id="l82" href="#l82">82</a> unlike modern lisps, is designed to be easy to implement. Writing a FORTH
92 <a id="l83" href="#l83">83</a> compiler is in fact a trivial exercise.
93 <a id="l84" href="#l84">84</a> 
94 <a id="l85" href="#l85">85</a> * Drawbacks
95 <a id="l86" href="#l86">86</a> ** Elispers might not want to read your Forthe code
96 <a id="l87" href="#l87">87</a> ** Forthe is not stable
97 <a id="l88" href="#l88">88</a>    FORTH is [[http://www.flownet.com/gat/jpl-lisp.html][space-age technology]], and Forthe is young. Send a pull request.
98 <a id="l89" href="#l89">89</a> ** Isn&#x27;t verbose code self-documenting?
99 <a id="l90" href="#l90">90</a> NO. Documented code is documented. Using short names with the bindings handily
100 <a id="l91" href="#l91">91</a> available in the same form is equally explicit as writing them out every time.
