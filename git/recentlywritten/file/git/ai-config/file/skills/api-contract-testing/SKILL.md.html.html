12 <a id="l3" href="#l3">3</a> description: Property-based testing of HTTP APIs against an OpenAPI or GraphQL specification using Schemathesis. Use when the project has an openapi.json, openapi.yaml, swagger.json, or an auto-generated spec (FastAPI /openapi.json, Django REST, Go/Java annotation-based specs); when adding or modifying an HTTP endpoint; when the spec and implementation may have drifted; or when a client reports a response shape the docs do not describe.

15 <a id="l6" href="#l6">6</a> # API contract testing
16 <a id="l7" href="#l7">7</a> 
17 <a id="l8" href="#l8">8</a> Schemathesis reads an OpenAPI spec, generates requests from the declared
18 <a id="l9" href="#l9">9</a> schemas, and checks that responses conform. It finds the two failure modes
19 <a id="l10" href="#l10">10</a> example tests never catch: inputs nobody thought to try, and drift between the
20 <a id="l11" href="#l11">11</a> spec and the implementation.
21 <a id="l12" href="#l12">12</a> 
22 <a id="l13" href="#l13">13</a> ## Preflight
23 <a id="l14" href="#l14">14</a> 
24 <a id="l15" href="#l15">15</a> ```bash
25 <a id="l16" href="#l16">16</a> command -v schemathesis || uvx schemathesis --help
26 <a id="l17" href="#l17">17</a> schemathesis --version
27 <a id="l18" href="#l18">18</a> ```
28 <a id="l19" href="#l19">19</a> 
29 <a id="l20" href="#l20">20</a> The CLI has changed across major versions (option names and defaults differ
30 <a id="l21" href="#l21">21</a> between v3 and v4). **Run `schemathesis run --help` and use what that reports**
31 <a id="l22" href="#l22">22</a> rather than relying on remembered flags. Report the version in the output.
32 <a id="l23" href="#l23">23</a> 
33 <a id="l24" href="#l24">24</a> Install: `uv tool install schemathesis`, or run ad hoc with `uvx schemathesis`.
34 <a id="l25" href="#l25">25</a> 
35 <a id="l26" href="#l26">26</a> ## Locating the spec
36 <a id="l27" href="#l27">27</a> 
37 <a id="l28" href="#l28">28</a> ```bash
38 <a id="l29" href="#l29">29</a> fd -e json -e yaml . | rg -i &#x27;openapi|swagger&#x27;
39 <a id="l30" href="#l30">30</a> curl -s localhost:8000/openapi.json | head -c 200      # FastAPI, Litestar
40 <a id="l31" href="#l31">31</a> curl -s localhost:8080/v3/api-docs | head -c 200       # springdoc
41 <a id="l32" href="#l32">32</a> ```
42 <a id="l33" href="#l33">33</a> 
43 <a id="l34" href="#l34">34</a> If the spec is generated at runtime, point Schemathesis at the live URL so it
44 <a id="l35" href="#l35">35</a> always tests the current contract. A stale checked-in spec tests nothing useful.
45 <a id="l36" href="#l36">36</a> 
46 <a id="l37" href="#l37">37</a> ## Baseline run
47 <a id="l38" href="#l38">38</a> 
48 <a id="l39" href="#l39">39</a> Start the service, then:
49 <a id="l40" href="#l40">40</a> 
50 <a id="l41" href="#l41">41</a> ```bash
51 <a id="l42" href="#l42">42</a> schemathesis run http://localhost:8000/openapi.json --url http://localhost:8000
52 <a id="l43" href="#l43">43</a> ```
53 <a id="l44" href="#l44">44</a> 
54 <a id="l45" href="#l45">45</a> Default checks cover: undocumented status codes, response bodies that violate
55 <a id="l46" href="#l46">46</a> the declared schema, wrong content types, malformed headers, and server errors
56 <a id="l47" href="#l47">47</a> (any 500 is a failure). Consult `--help` for the current check list and for how
57 <a id="l48" href="#l48">48</a> to select or exclude individual checks.
58 <a id="l49" href="#l49">49</a> 
59 <a id="l50" href="#l50">50</a> Useful controls (verify names against `--help`):
60 <a id="l51" href="#l51">51</a> 
61 <a id="l52" href="#l52">52</a> - Limit scope while iterating: filter by path or method rather than running the
62 <a id="l53" href="#l53">53</a>   whole surface on every change.
63 <a id="l54" href="#l54">54</a> - `--max-examples` — raise for a thorough run, lower for a fast inner loop.
64 <a id="l55" href="#l55">55</a> - Authentication: `-H &quot;Authorization: Bearer $TOKEN&quot;`, or `--auth user:pass`.
65 <a id="l56" href="#l56">56</a> - `--report` / cassette output — records failing interactions for replay.
66 <a id="l57" href="#l57">57</a> 
67 <a id="l58" href="#l58">58</a> ## Interpreting failures
68 <a id="l59" href="#l59">59</a> 
69 <a id="l60" href="#l60">60</a> Schemathesis reports a minimised failing case plus a `curl` command that
70 <a id="l61" href="#l61">61</a> reproduces it. Triage into three buckets — the classification matters more than
71 <a id="l62" href="#l62">62</a> the fix:
72 <a id="l63" href="#l63">63</a> 
73 <a id="l64" href="#l64">64</a> 1. **The implementation is wrong.** Fix the code. Add the minimised case as a
74 <a id="l65" href="#l65">65</a>    unit test first, and show it failing.
75 <a id="l66" href="#l66">66</a> 2. **The spec is wrong.** Fix the spec. This is common and valuable: the spec is
76 <a id="l67" href="#l67">67</a>    what clients and codegen consume, so a wrong spec is a live bug even when the
77 <a id="l68" href="#l68">68</a>    server behaves correctly. Do not loosen the spec merely to silence a failure
78 <a id="l69" href="#l69">69</a>    — that discards the signal.
79 <a id="l70" href="#l70">70</a> 3. **The generated input is genuinely invalid** and the spec failed to say so.
80 <a id="l71" href="#l71">71</a>    Tighten the schema (`minLength`, `pattern`, `format`, `enum`, `minimum`).
81 <a id="l72" href="#l72">72</a>    This is the best outcome: the spec becomes more precise, and downstream
82 <a id="l73" href="#l73">73</a>    codegen and validation improve for free.
83 <a id="l74" href="#l74">74</a> 
84 <a id="l75" href="#l75">75</a> A 500 on any generated input is always bucket 1. Malformed input must produce a
85 <a id="l76" href="#l76">76</a> 4xx, never an unhandled exception.
86 <a id="l77" href="#l77">77</a> 
87 <a id="l78" href="#l78">78</a> ## Stateful testing
88 <a id="l79" href="#l79">79</a> 
89 <a id="l80" href="#l80">80</a> Schemathesis can chain requests using OpenAPI `links` to test sequences
90 <a id="l81" href="#l81">81</a> (create → read → update → delete), catching bugs that single-request tests miss.
91 <a id="l82" href="#l82">82</a> This requires `links` to be declared in the spec. Check current syntax with
92 <a id="l83" href="#l83">83</a> `--help`; if links are absent, adding them improves both the docs and the tests.
93 <a id="l84" href="#l84">84</a> 
94 <a id="l85" href="#l85">85</a> ## In the test suite
95 <a id="l86" href="#l86">86</a> 
96 <a id="l87" href="#l87">87</a> Prefer running Schemathesis in-process against the ASGI/WSGI app rather than
97 <a id="l88" href="#l88">88</a> over the network — faster, no port juggling, works in CI without a service
98 <a id="l89" href="#l89">89</a> container. The Python API for this has changed between major versions; consult
99 <a id="l90" href="#l90">90</a> the installed version&#x27;s documentation rather than assuming the decorator name.
100 <a id="l91" href="#l91">91</a> 
101 <a id="l92" href="#l92">92</a> Whichever form is used, drive it against the app object, seed any required auth
102 <a id="l93" href="#l93">93</a> via fixtures, and commit every discovered failing case as an ordinary example
103 <a id="l94" href="#l94">94</a> test so it stays covered after the fuzzing budget moves on.
104 <a id="l95" href="#l95">95</a> 
105 <a id="l96" href="#l96">96</a> ## CI
106 <a id="l97" href="#l97">97</a> 
107 <a id="l98" href="#l98">98</a> Run a bounded pass on every PR (low `--max-examples`, fail on any error) and a
108 <a id="l99" href="#l99">99</a> longer scheduled run nightly. Treat spec changes as API changes: if a PR alters
109 <a id="l100" href="#l100">100</a> the spec, say so in the summary, and check whether the change is
110 <a id="l101" href="#l101">101</a> backwards-compatible for existing clients.
111 <a id="l102" href="#l102">102</a> 
112 <a id="l103" href="#l103">103</a> ## Not an OpenAPI project?
113 <a id="l104" href="#l104">104</a> 
114 <a id="l105" href="#l105">105</a> - GraphQL: Schemathesis supports GraphQL schemas directly.
115 <a id="l106" href="#l106">106</a> - gRPC/protobuf: use `buf breaking` for compatibility checks plus property
116 <a id="l107" href="#l107">107</a>   tests over the generated types.
117 <a id="l108" href="#l108">108</a> - No spec at all: consider whether one is warranted. If the API is internal and
118 <a id="l109" href="#l109">109</a>   small, plain property tests over the handler functions are cheaper and give
119 <a id="l110" href="#l110">110</a>   most of the benefit.</pre>
