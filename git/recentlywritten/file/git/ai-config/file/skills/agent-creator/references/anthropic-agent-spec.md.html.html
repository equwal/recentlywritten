14 <a id="l5" href="#l5">5</a> ## Supported Frontmatter Fields
15 <a id="l6" href="#l6">6</a>

39 <a id="l30" href="#l30">30</a> ## Key Facts
40 <a id="l31" href="#l31">31</a> 
41 <a id="l32" href="#l32">32</a> - The **body** (markdown after frontmatter) becomes the **system prompt** that guides the subagent
42 <a id="l33" href="#l33">33</a> - Subagents receive ONLY the system prompt + basic environment details, NOT the full Claude Code system prompt
43 <a id="l34" href="#l34">34</a> - `tools` is an **allowlist** (like skills&#x27; `allowed-tools`)
44 <a id="l35" href="#l35">35</a> - `disallowedTools` is a **denylist** — if both set, disallowed applied first, then tools resolved
45 <a id="l36" href="#l36">36</a> - Naming parallel (marketplace note): agents use camelCase `disallowedTools`; skills use kebab-case `disallowed-tools` (schema 3.7.0+). The validator rejects either mismatch — never copy-paste between agent and skill frontmatter without renaming
46 <a id="l37" href="#l37">37</a> - Subagents **cannot spawn other subagents** (no nesting)
47 <a id="l38" href="#l38">38</a> - Subagents **don&#x27;t inherit skills** from parent conversation — must list explicitly via `skills` field
48 <a id="l39" href="#l39">39</a> 
49 <a id="l40" href="#l40">40</a> ## Plugin Agent Restrictions
50 <a id="l41" href="#l41">41</a> 
51 <a id="l42" href="#l42">42</a> Plugin agents (`plugins/*/agents/*.md`) do NOT support:
52 <a id="l43" href="#l43">43</a> 
53 <a id="l44" href="#l44">44</a> - `hooks` — ignored when loading from plugin
54 <a id="l45" href="#l45">45</a> - `mcpServers` — ignored when loading from plugin
55 <a id="l46" href="#l46">46</a> - `permissionMode` — ignored when loading from plugin
56 <a id="l47" href="#l47">47</a> 
57 <a id="l48" href="#l48">48</a> These are standalone-only features. If needed, copy the agent to `.claude/agents/` or `~/.claude/agents/`.
58 <a id="l49" href="#l49">49</a> 
59 <a id="l50" href="#l50">50</a> ## Tool Scoping
60 <a id="l51" href="#l51">51</a> 
61 <a id="l52" href="#l52">52</a> Subagents can use `Agent(type)` syntax to restrict which subagents they can spawn (only for main-thread agents via `--agent`).
62 <a id="l53" href="#l53">53</a> 
63 <a id="l54" href="#l54">54</a> ## Skills Preloading
64 <a id="l55" href="#l55">55</a> 
65 <a id="l56" href="#l56">56</a> ```yaml
66 <a id="l57" href="#l57">57</a> skills:
67 <a id="l58" href="#l58">58</a>   - api-conventions
68 <a id="l59" href="#l59">59</a>   - error-handling-patterns
69 <a id="l60" href="#l60">60</a> ```
70 <a id="l61" href="#l61">61</a> 
71 <a id="l62" href="#l62">62</a> Full content of each skill is injected at startup. This is the inverse of `context: fork` in skills.
