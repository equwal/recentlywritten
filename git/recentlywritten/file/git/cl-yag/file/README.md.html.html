13 <a id="l4" href="#l4">4</a> ## Introduction
14 <a id="l5" href="#l5">5</a> 
15 <a id="l6" href="#l6">6</a> cl-yag is a lightweight, static site generator that produces **gopher**
16 <a id="l7" href="#l7">7</a> and **gemini** sites (and is easily extensible to more formats) as
17 <a id="l8" href="#l8">8</a> well as **html** websites.  The name &#x27;cl-yag&#x27; stands for &#x27;Common Lisp
18 <a id="l9" href="#l9">9</a> - Yet Another website Generator&#x27;.  It runs without needing Quicklisp
19 <a id="l10" href="#l10">10</a> (Common LISP library manager).
20 <a id="l11" href="#l11">11</a>

50 <a id="l41" href="#l41">41</a> ## Requirements
51 <a id="l42" href="#l42">42</a> 
52 <a id="l43" href="#l43">43</a> To use cl-yag you&#x27;ll need:
53 <a id="l44" href="#l44">44</a> 
54 <a id="l45" href="#l45">45</a> 1. Any Common Lisp Interpreter and the ASDF package system
55 <a id="l46" href="#l46">46</a>     - cl-yag&#x27;s current default is [Embeddable Common Lisp (ECL)](https://common-lisp.net/project/ecl/).
56 <a id="l47" href="#l47">47</a>     - [Steel Bank Common Lisp (SBCL)](http://www.sbcl.org/) will do fine as well.
57 <a id="l48" href="#l48">48</a> 
58 <a id="l49" href="#l49">49</a> 2. A Converter for arbitrary formats
59 <a id="l50" href="#l50">50</a>     - cl-yag&#x27;s current default is [multimarkdown](http://fletcherpenney.net/multimarkdown/).
60 <a id="l51" href="#l51">51</a>     - pandoc could work fine too
61 <a id="l52" href="#l52">52</a>     - each post can have its own converter as needed (great if importing your site from elsewhere)

63 <a id="l54" href="#l54">54</a> ## Usage
64 <a id="l55" href="#l55">55</a> 
65 <a id="l56" href="#l56">56</a> Go into your project&#x27;s directory and type ``make``. You&#x27;ll find your
66 <a id="l57" href="#l57">57</a> new website/gopher/gemini page in **output/**.  If you want to get rid
67 <a id="l58" href="#l58">58</a> of everything in your **output/** sub directories, type ``make clean``.
68 <a id="l59" href="#l59">59</a> For further commands: read the Makefile. Read in the following section
69 <a id="l60" href="#l60">60</a> where to find it.
70 <a id="l61" href="#l61">61</a> 
71 <a id="l62" href="#l62">62</a> It is necessary to edit the ``data/articles.lisp`` file which is the
72 <a id="l63" href="#l63">63</a> user configuration for the site.
73 <a id="l64" href="#l64">64</a>

138 <a id="l129" href="#l129">129</a> ## Configuration
139 <a id="l130" href="#l130">130</a> 
140 <a id="l131" href="#l131">131</a> cl-yag&#x27;s main configuration file is **data/articles.lisp**.  
141 <a id="l132" href="#l132">132</a> In order to have a running implementation of cl-yag, you have
142 <a id="l133" href="#l133">133</a> to set most of the values in this file.
143 <a id="l134" href="#l134">134</a> 
144 <a id="l135" href="#l135">135</a> **data/articles.lisp** has two parts:
145 <a id="l136" href="#l136">136</a> 
146 <a id="l137" href="#l137">137</a> 1. A variable called *config*. Its values define your web page.
147 <a id="l138" href="#l138">138</a> 2. &quot;posts&quot; declaration with their meta-data
148 <a id="l139" href="#l139">139</a> 
149 <a id="l140" href="#l140">140</a> Values are assigned by placing a string (e.g. ``&quot;foo&quot;``) or a boolean
150 <a id="l141" href="#l141">141</a> (i.e. ``t`` or ``nil``) behind a keyword (e.g. ``:title``).
151 <a id="l142" href="#l142">142</a> 
152 <a id="l143" href="#l143">143</a> 
153 <a id="l144" href="#l144">144</a> ### The *config* Variable
154 <a id="l145" href="#l145">145</a> 
155 <a id="l146" href="#l146">146</a> The *config* variable is used to assign the following values:
156 <a id="l147" href="#l147">147</a> 
157 <a id="l148" href="#l148">148</a> - **:webmaster**
158 <a id="l149" href="#l149">149</a>     - The name of the default(!) author. 
159 <a id="l150" href="#l150">150</a> 	- ``:webmaster`` gets used, if ``:author`` is omitted. (See below: &#x27;The **articles** variable&#x27;.)
160 <a id="l151" href="#l151">151</a> - **:title**
161 <a id="l152" href="#l152">152</a>     - The title of the web-page
162 <a id="l153" href="#l153">153</a> - **:description**
163 <a id="l154" href="#l154">154</a>     - This text is used in the *description* field of the atom/rss feed.
164 <a id="l155" href="#l155">155</a> - **:url**
165 <a id="l156" href="#l156">156</a>     - This needs to be the full(!) URL of your website, including(!) a final slash.
166 <a id="l157" href="#l157">157</a> 	- MIND: If the url contains a tilde (~), it needs to get duplicated.
167 <a id="l158" href="#l158">158</a> 	- Example: ``https://mydomain/~~user/``
168 <a id="l159" href="#l159">159</a> - **:rss-item-number**
169 <a id="l160" href="#l160">160</a>     - This holds the number of latest(!) RSS items you want to get published.
170 <a id="l161" href="#l161">161</a> - **html**
171 <a id="l162" href="#l162">162</a>     - ``t`` to export html website. Set ``nil`` to disable.
172 <a id="l163" href="#l163">163</a> - **gopher**
173 <a id="l164" href="#l164">164</a>     - ``t`` to export gopher website. Set ``nil`` to disable.
174 <a id="l165" href="#l165">165</a> - **gopher-path**
175 <a id="l166" href="#l166">166</a>     - This is the full path of the directory to access your gopher hole.
176 <a id="l167" href="#l167">167</a> - **gopher-server**
177 <a id="l168" href="#l168">168</a>     - Hostname of the gopher server. It needs to be included in each link.
178 <a id="l169" href="#l169">169</a> - **gopher-port**
179 <a id="l170" href="#l170">170</a>     - tcp port of the gopher server. 70 is the default port. It needs to be included in each link.
180 <a id="l171" href="#l171">171</a> - **gopher-format**
181 <a id="l172" href="#l172">172</a>     - format of the gopher server. default is the geomyidae format, gophernicus format is commented.
182 <a id="l173" href="#l173">173</a> - **gopher-index**
183 <a id="l174" href="#l174">174</a>     - name of the gopher menu file. default is index.gph for geomyidae, gophermap file is commented.
184 <a id="l175" href="#l175">175</a> 
185 <a id="l176" href="#l176">176</a> 
186 <a id="l177" href="#l177">177</a> ### Posts declarations
187 <a id="l178" href="#l178">178</a> 
188 <a id="l179" href="#l179">179</a> Each post is declared with its meta-data using the function &quot;post&quot;.
189 <a id="l180" href="#l180">180</a> So you need to add a new line for each of your posts.
190 <a id="l181" href="#l181">181</a> 
191 <a id="l182" href="#l182">182</a> Of the following keywords, only ``:author`` and ``:short`` can be omitted.
192 <a id="l183" href="#l183">183</a> 
193 <a id="l184" href="#l184">184</a> - **:author**
194 <a id="l185" href="#l185">185</a>     - The ``:author`` field is used to display the article&#x27;s author.
195 <a id="l186" href="#l186">186</a>     - If you omit it, the generator will take the name from the ``:webmaster`` field of the *config* variable.
196 <a id="l187" href="#l187">187</a> - **:id**
197 <a id="l188" href="#l188">188</a>     - The ``:id`` field holds the file name of your post/page.
198 <a id="l189" href="#l189">189</a> 	- Example: ``:id &quot;2&quot;`` will load file **data/2.md**. Use text instead of numbers, if you want to.
199 <a id="l190" href="#l190">190</a> 	- (See section: &#x27;The **data/** Directory&#x27;.)
200 <a id="l191" href="#l191">191</a> - **:tag**
201 <a id="l192" href="#l192">192</a>     - ``:tag`` field is used to create a &quot;view&quot; containing all articles of the same tag.
202 <a id="l193" href="#l193">193</a> 	-  MIND: White spaces are used to separate tags and are not allowed in(!) tags.
203 <a id="l194" href="#l194">194</a> - **:tiny**
204 <a id="l195" href="#l195">195</a> 	- The ``:tiny`` field&#x27;s value is used for displaying a really short description of the posts content on your homepage.
205 <a id="l196" href="#l196">196</a> 	- If ``:tiny`` doesn&#x27;t get a value, the full article gets displayed.
206 <a id="l197" href="#l197">197</a> 	- Hint: Use ``:tiny &quot;Read the full article for more information.&quot;``, if you don&#x27;t want to display the full text of an article on your index site.
207 <a id="l198" href="#l198">198</a> - **:title**
208 <a id="l199" href="#l199">199</a> 	- The ``:title`` field&#x27;s value sets your post&#x27;s title, its first headline, as well as its entry on the index.html.
209 <a id="l200" href="#l200">200</a> 
210 <a id="l201" href="#l201">201</a> ### Generator registering
211 <a id="l202" href="#l202">202</a> 
212 <a id="l203" href="#l203">203</a> Each generator is registered in the user config. To not generate something, just comment out the registry for that
213 <a id="l204" href="#l204">204</a> generator.

230 <a id="l221" href="#l221">221</a> ## How-to Publish A Post
231 <a id="l222" href="#l222">222</a> 
232 <a id="l223" href="#l223">223</a> I prepared a Makefile to facilitate the process of generating and
233 <a id="l224" href="#l224">224</a> publishing your static sites.
234 <a id="l225" href="#l225">225</a> All you need to do in order to publish is to go into your cl-yag
235 <a id="l226" href="#l226">226</a> directory and type ``make``.
236 <a id="l227" href="#l227">227</a> 
237 <a id="l228" href="#l228">228</a> The make command creates html and gopher files in the defined location.
238 <a id="l229" href="#l229">229</a> The default is the **output/** directory, but you can use a symbolic link
239 <a id="l230" href="#l230">230</a> pointing to some other directory as well.
240 <a id="l231" href="#l231">231</a> 
241 <a id="l232" href="#l232">232</a> 
242 <a id="l233" href="#l233">233</a> ## How-to Add A New Page
243 <a id="l234" href="#l234">234</a> 
244 <a id="l235" href="#l235">235</a> You may want to have some dedicated pages besides the index or a post.
245 <a id="l236" href="#l236">236</a> To create one, edit the *generate-site* function in cl-yag&#x27;s
246 <a id="l237" href="#l237">237</a> **generator.lisp** and add a function call, like this:
247 <a id="l238" href="#l238">238</a> 
248 <a id="l239" href="#l239">239</a>     (generate &quot;somepage.html&quot; (load-file &quot;data/mypage.html&quot;))
249 <a id="l240" href="#l240">240</a>   
250 <a id="l241" href="#l241">241</a> This will produce **output/html/somepage.html**.
251 <a id="l242" href="#l242">242</a>

254 <a id="l245" href="#l245">245</a> 
255 <a id="l246" href="#l246">246</a> ### How-to Use Another Common Lisp Interpreter

261 <a id="l252" href="#l252">252</a>     make LISP=ecl

267 <a id="l258" href="#l258">258</a> hook to call the make program after each change in the repo so your
268 <a id="l259" href="#l259">259</a> website gets updated automatically.

271 <a id="l262" href="#l262">262</a> ## Page-Includes
272 <a id="l263" href="#l263">263</a> 
273 <a id="l264" href="#l264">264</a> Here is an example code, if you want to include another page in the template:
274 <a id="l265" href="#l265">265</a> 
275 <a id="l266" href="#l266">266</a> 1. Create **templates/panel.tpl** containing the html you want to include.
276 <a id="l267" href="#l267">267</a> 2. Add a replacement-string in the target file, where the replacement should occur.  
277 <a id="l268" href="#l268">268</a>    In this case, we choose **%%Panel%%** for a string, and, because we want the panel to be displayed on each page, we add this string to **templates/layout.tpl**.
278 <a id="l269" href="#l269">269</a> 
279 <a id="l270" href="#l270">270</a> 3. Modify the function *generate-layout* in cl-yag&#x27;s **generator.lisp** accordingly.  
280 <a id="l271" href="#l271">271</a>    This is done by adding the following template function call:
281 <a id="l272" href="#l272">272</a> 
282 <a id="l273" href="#l273">273</a> 		(template &quot;%%Panel%%&quot; (load-file &quot;templates/panel.tpl&quot;))
283 <a id="l274" href="#l274">274</a> 
284 <a id="l275" href="#l275">275</a> Another valid approach is to writer your html directly into **templates/layout.tpl**.
285 <a id="l276" href="#l276">276</a> 
286 <a id="l277" href="#l277">277</a> ## Known Limitations
287 <a id="l278" href="#l278">278</a> 
288 <a id="l279" href="#l279">279</a> ### Use ~~ To Create ~
289 <a id="l280" href="#l280">280</a> 
290 <a id="l281" href="#l281">281</a> cl-yag crashes if you use a single &quot;~&quot; character inside
291 <a id="l282" href="#l282">282</a> **templates/articles.lisp**, because Common Lisp employs the tilde as a
292 <a id="l283" href="#l283">283</a> prefix to indicate format specifiers in format strings.
293 <a id="l284" href="#l284">284</a> 
294 <a id="l285" href="#l285">285</a> In order to use a literal `~` -- e.g. for creating a ``:title`` or
295 <a id="l286" href="#l286">286</a> ``:url`` reference -- you have to *escape* the tilde *by
296 <a id="l287" href="#l287">287</a> duplicating* it: ``~~``.  (See ``:url`` in section &#x27;Configuration&#x27;).
297 <a id="l288" href="#l288">288</a> 
298 <a id="l289" href="#l289">289</a> 
299 <a id="l290" href="#l290">290</a> ### Posting Without Tagging
300 <a id="l291" href="#l291">291</a> 
301 <a id="l292" href="#l292">292</a> cl-yag allows posts without tags, but, using the default
302 <a id="l293" href="#l293">293</a> **templates/layout.tpl**, you&#x27;ll get a line below your title that
303 <a id="l294" href="#l294">294</a> displays: &quot;Tags: &quot;.
304 <a id="l295" href="#l295">295</a> 
305 <a id="l296" href="#l296">296</a> (Note: If you are looking for a way to contribute this may be a task for you.)
306 <a id="l297" href="#l297">297</a> 
307 <a id="l298" href="#l298">298</a> 
308 <a id="l299" href="#l299">299</a> ### A Note On Themes
309 <a id="l300" href="#l300">300</a> 
310 <a id="l301" href="#l301">301</a> Although cl-yag may ship with a minimalist template, cl-yag focuses
311 <a id="l302" href="#l302">302</a> on generating html- and gopher-compliant structural markup - not
312 <a id="l303" href="#l303">303</a> themed layouts.
313 <a id="l304" href="#l304">304</a> 
314 <a id="l305" href="#l305">305</a> If you want some deeply refined, cross-browser compatible, responsive,
315 <a id="l306" href="#l306">306</a> webscale style sheets, you need to create them yourself.  However,
316 <a id="l307" href="#l307">307</a> cl-yag will work nicely with them and if you want to make your
317 <a id="l308" href="#l308">308</a> style sheets a part of cl-yag you&#x27;re very welcome to contact me.
318 <a id="l309" href="#l309">309</a> 
319 <a id="l310" href="#l310">310</a> ### New Generators
320 <a id="l311" href="#l311">311</a> 
321 <a id="l312" href="#l312">312</a> 1. Add a lisp file to generators/ which does the necessary work. See the other ones for comparison.
322 <a id="l313" href="#l313">313</a> 2. Add it to the **cl-yag.asd** file with the other generators (order is important).
323 <a id="l314" href="#l314">314</a> 3. `register` it in **data/articles.lisp**
324 <a id="l315" href="#l315">315</a> 4. Contribute it.
