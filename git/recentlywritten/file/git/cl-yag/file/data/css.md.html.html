30 <a id="l21" href="#l21">21</a> ## style.css -- One Sheet To Rule Them All
31 <a id="l22" href="#l22">22</a> 
32 <a id="l23" href="#l23">23</a> In order to keep it simple cl-yag uses **static/css/style.css** to
33 <a id="l24" href="#l24">24</a> administrate all of its style sheets. Use the ``@import`` rule to
34 <a id="l25" href="#l25">25</a> include your own, or comments to get rid of what is already there -
35 <a id="l26" href="#l26">26</a> but mind the [cascade](https://www.w3.org/TR/css-cascade-3/ &quot;W3C: CSS Cascading and Inheritance Level 3&quot;).
36 <a id="l27" href="#l27">27</a> 
37 <a id="l28" href="#l28">28</a> Currently, **style.css** looks like this:
38 <a id="l29" href="#l29">29</a>

59 <a id="l50" href="#l50">50</a> ## Pure -- &quot;A Set Of Small, Responsive CSS Modules&quot;
60 <a id="l51" href="#l51">51</a> 
61 <a id="l52" href="#l52">52</a> cl-yag uses a style sheet called **pure.css**, taken from
62 <a id="l53" href="#l53">53</a> [Pure](https://purecss.io/ &quot;purecss.io&quot;), a minimal, BSD licensed CSS
63 <a id="l54" href="#l54">54</a> framework, to provide a set of expected UI features, among which are
64 <a id="l55" href="#l55">55</a> sane resets (such as
65 <a id="l56" href="#l56">56</a> [normalize.css](https://necolas.github.io/normalize.css/
66 <a id="l57" href="#l57">57</a> &quot;Normalize.css - A modern, HTML5-ready alternative to CSS resets&quot;)&#x27;s
67 <a id="l58" href="#l58">58</a> reset rules) and usable menus.
68 <a id="l59" href="#l59">59</a> 
69 <a id="l60" href="#l60">60</a> To deactivate Pure, put the *PURE.CSS* ``@import`` rule in
70 <a id="l61" href="#l61">61</a> **static/css/style.css** in comments and re-run ``make``.
71 <a id="l62" href="#l62">62</a>

73 <a id="l64" href="#l64">64</a> ## clym -- A Default Theme
74 <a id="l65" href="#l65">65</a> 
75 <a id="l66" href="#l66">66</a> Additionally, cl-yag comes with its first theme: *clym*.
76 <a id="l67" href="#l67">67</a> 
77 <a id="l68" href="#l68">68</a> *clym* stands for *cl-yag minimal*. It is a set of css rules designed to
78 <a id="l69" href="#l69">69</a> work with cl-yag&#x27;s html skeleton. It provides an unobtrusive color
79 <a id="l70" href="#l70">70</a> scheme, basic typography, as well as basic responsiveness. You&#x27;ll find
80 <a id="l71" href="#l71">71</a> it in **static/css/clym.css**.
81 <a id="l72" href="#l72">72</a> 
82 <a id="l73" href="#l73">73</a> **clym.css** doesn&#x27;t provide neither css resets nor a menu layout. This
83 <a id="l74" href="#l74">74</a> is handled by [Pure](https://purecss.io/ &quot;purecss.io&quot;)&#x27;s
84 <a id="l75" href="#l75">75</a> **pure.css**. Further, it doesn&#x27;t need any JavaScript.
85 <a id="l76" href="#l76">76</a> 
86 <a id="l77" href="#l77">77</a> If you don&#x27;t like *clym*, put comments around the line ``@import
87 <a id="l78" href="#l78">78</a> url(&quot;clym.css&quot;);`` in **static/css/style.css**, around all pure-rules
88 <a id="l79" href="#l79">79</a> in **static/css/custom.css**, and re-run ``make``.

99 <a id="l90" href="#l90">90</a> ### Current Styles And Minor Tweaks
100 <a id="l91" href="#l91">91</a> 
101 <a id="l92" href="#l92">92</a> If you are already using a combination of style sheets and you need to
102 <a id="l93" href="#l93">93</a> adjust some parts of the layout, use cl-yag&#x27;s
103 <a id="l94" href="#l94">94</a> **static/css/custom.css**. It is currently used to override Pure&#x27;s
104 <a id="l95" href="#l95">95</a> default layout for horizontal menus with *clym*&#x27;s colorscheme.
105 <a id="l96" href="#l96">96</a> 
106 <a id="l97" href="#l97">97</a> #### MIND
107 <a id="l98" href="#l98">98</a> 
108 <a id="l99" href="#l99">99</a> - In order to override rules located in all previous(!) style sheets
109 <a id="l100" href="#l100">100</a> **custom.css** needs to get sourced in as the last(!)  file in
110 <a id="l101" href="#l101">101</a> **static/css/style.css** (see section: &quot;style.css – One Sheet To Rule Them
111 <a id="l102" href="#l102">102</a> All&quot;).
112 <a id="l103" href="#l103">103</a> - Respect the [cascade](https://www.w3.org/TR/css-cascade-3/ &quot;W3C: CSS Cascading and Inheritance Level 3&quot;) :-).

115 <a id="l106" href="#l106">106</a> ### Frameworks
116 <a id="l107" href="#l107">107</a> 
117 <a id="l108" href="#l108">108</a> CSS frameworks provide an easy way to create your own theme. To make use
118 <a id="l109" href="#l109">109</a> of a framework&#x27;s rulesets,
119 <a id="l110" href="#l110">110</a> 
120 <a id="l111" href="#l111">111</a> - its style sheets need to get included via your **static/css/style.css**,
121 <a id="l112" href="#l112">112</a> - their ids and classes need to get wired into cl-yag&#x27;s template files and
122 <a id="l113" href="#l113">113</a> - the template files need to get used by cl-yag&#x27;s **generator.lisp**.
123 <a id="l114" href="#l114">114</a> 
124 <a id="l115" href="#l115">115</a> So you need to edit cl-yag&#x27;s template files in **templates/** and - in
125 <a id="l116" href="#l116">116</a> case you&#x27;ve choosen to rename your templates - you need to adjust their
126 <a id="l117" href="#l117">117</a> corresponding paths and filenames in **generator.lisp**.
