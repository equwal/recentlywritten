10 <p>README.md (7405 bytes)</p><pre class="src"><a id="l1" href="#l1">1</a> # Brainfuck from within Common Lisp
11 <a id="l2" href="#l2">2</a> LispFuck is a simple Brainfuck interpreter written in Common Lisp. It has the best brainfuck debugging capabilities currently in existence, and code can be interpreted or compiled. Users may: view the tape contents or individual cell contents, find the final position of execution in the tape, change the length of the byte tape in the REPL, and more.
12 <a id="l3" href="#l3">3</a> [![Picture of Emacs REPL](https://raw.githubusercontent.com/equwal/LispFuck/master/pics/repl.png)](https://raw.githubusercontent.com/equwal/LispFuck/master/pics/repl.png)

14 <a id="l5" href="#l5">5</a> # Brainfuck
15 <a id="l6" href="#l6">6</a> Brainfuck is an esoteric programming language that works on a theoretical byte tape (the Universal Turing Machine). The commands are:
16 <a id="l7" href="#l7">7</a> ```
17 <a id="l8" href="#l8">8</a> &gt; Move to the next byte on the right.
18 <a id="l9" href="#l9">9</a> &lt; Move to the next byte on the left.
19 <a id="l10" href="#l10">10</a> . Print the current byte using ASCII.
20 <a id="l11" href="#l11">11</a> , Read a character of input into this byte.
21 <a id="l12" href="#l12">12</a> + Increment this byte&#x27;s value by one. If the cell value is 255 then set it to 0.
22 <a id="l13" href="#l13">13</a> - Decrease the value of this cell by one. If the cell value is 0 then set it to 255.
23 <a id="l14" href="#l14">14</a> [ Start a loop. It will be skipped if the current byte is zero, and if not it will terminate at the
24 <a id="l15" href="#l15">15</a>   following &quot;]&quot; when the cell is finally set to zero.
25 <a id="l16" href="#l16">16</a> ] Delimit the end of a loop. 
26 <a id="l17" href="#l17">17</a> Any other character is considered a &quot;comment&quot; meaning it does nothing.
27 <a id="l18" href="#l18">18</a> ```
28 <a id="l19" href="#l19">19</a> 
29 <a id="l20" href="#l20">20</a> These can be combined into a string such as the following &quot;Hello World!&quot; program:
30 <a id="l21" href="#l21">21</a> ```
31 <a id="l22" href="#l22">22</a> &gt; #f++++++++[&gt;++++[&gt;++&gt;+++&gt;+++&gt;+&lt;&lt;&lt;&lt;-]&gt;+&gt;+&gt;-&gt;&gt;+[&lt;]&lt;-]&gt;&gt;.&gt;---.+++++++..+++.&gt;&gt;.&lt;-.&lt;.+++.------.--------.&gt;&gt;+.&gt;++.
32 <a id="l23" href="#l23">23</a> &quot;Hello World!
33 <a id="l24" href="#l24">24</a> &quot;
34 <a id="l25" href="#l25">25</a> ```
35 <a id="l26" href="#l26">26</a> # How to install:
36 <a id="l27" href="#l27">27</a> - Make sure you have a Common Lisp implementation installed. I recommend [Steel Bank Common Lisp](http://www.sbcl.org/).
37 <a id="l28" href="#l28">28</a> - [ASDF](https://common-lisp.net/project/asdf/) must be installed. Many Lisps come with it, no installation necessary (including [SBCL](http://www.sbcl.org/)).
38 <a id="l29" href="#l29">29</a> - Install this code into your ASDF *load directory*. The default on linux is usually `~/common-lisp/`:
39 <a id="l30" href="#l30">30</a> ```
40 <a id="l31" href="#l31">31</a> me@linux:~$ mkdir common-lisp
41 <a id="l32" href="#l32">32</a> me@linux:~$ cd common-lisp
42 <a id="l33" href="#l33">33</a> me@linux:~/common-lisp$ git clone https://github.com/equwal/LispBrain.git
43 <a id="l34" href="#l34">34</a> ```
44 <a id="l35" href="#l35">35</a> - Run your favourite Common Lisp implementation and load the :brain package:
45 <a id="l36" href="#l36">36</a> ```
46 <a id="l37" href="#l37">37</a> &gt; (asdf:load-system :brain)
47 <a id="l38" href="#l38">38</a> ```
48 <a id="l39" href="#l39">39</a> 
49 <a id="l40" href="#l40">40</a> If you are unable to find where the ASDF load directory is, you may choose to load the files thusly:
50 <a id="l41" href="#l41">41</a> ```
51 <a id="l42" href="#l42">42</a> &gt; (load &quot;[filepath]/code/packages.lisp&quot;)
52 <a id="l43" href="#l43">43</a> &gt; (load &quot;[filepath]/code/interpreter.lisp&quot;)
53 <a id="l44" href="#l44">44</a> &gt; (load &quot;[filepath]/code/brain.asd&quot;)
54 <a id="l45" href="#l45">45</a> &gt; (asdf:load-system :brain)
55 <a id="l46" href="#l46">46</a> ```
56 <a id="l47" href="#l47">47</a> 
57 <a id="l48" href="#l48">48</a> In Allegro common lisp one must first use `(require :asdf)` before executing any other commands in order to activate the preinstalled ASDF system.

88 <a id="l79" href="#l79">79</a> Code can be saved in a file and run at the repl with the `(load &quot;filepath&quot;)` command, and compiled with the `(compile-file &quot;filepath&quot;)` command. [SBCL](http://www.sbcl.org/) will always compile your code for you. I recommend not compiling code unless speed is truly important; compiling can make the debugging capabilities of Common Lisp implementations less usable.

90 <a id="l81" href="#l81">81</a> # Debugging Brainfuck
91 <a id="l82" href="#l82">82</a> 
92 <a id="l83" href="#l83">83</a> Debugging Brainfuck code can be done using all the normal Common Lisp functions: `step`, `trace`, `time`, etc. The following functions and variables are exported to the user and may be useful for debugging Brainfuck code:
93 <a id="l84" href="#l84">84</a> ```
94 <a id="l85" href="#l85">85</a> brain:fuck                ;Used to execute a Brainfuck string directly.
95 <a id="l86" href="#l86">86</a> brain:*tape-size-default* ;Number of cells in the tape. Default: 30,000.
96 <a id="l87" href="#l87">87</a> brain:decf-byte           ;The - operator function.
97 <a id="l88" href="#l88">88</a> brain:incf-byte           ;The + operator function.
98 <a id="l89" href="#l89">89</a> brain:read-this-byte      ;The , operator function.
99 <a id="l90" href="#l90">90</a> brain:print-this-byte     ;The . operator function.
100 <a id="l91" href="#l91">91</a> brain:right-shift         ;The &gt; operator function.
101 <a id="l92" href="#l92">92</a> brain:left-shift          ;The &lt; operator function.
102 <a id="l93" href="#l93">93</a> brain:one-off-fuck        ;Function called to loop over each character in the code.
103 <a id="l94" href="#l94">94</a> brain:*separators*        ;Characters that terminate #F Brainfuck code. Defaults: #\Space #\) #\Newline.
104 <a id="l95" href="#l95">95</a> brain:byte-value          ;Returns the value of the curren byte at the *pointer* position.
105 <a id="l96" href="#l96">96</a> brain:*tape*              ;Stores the entire tape.
106 <a id="l97" href="#l97">97</a> brain:*pointer*           ;Stores the current position in the byte tape. Useful with byte-value. 
107 <a id="l98" href="#l98">98</a>                               Default: Exactly in the middle of the tape (15,000).
108 <a id="l99" href="#l99">99</a> ```
109 <a id="l100" href="#l100">100</a> Note that the variables `*tape*` and `*pointer*` are reset upon executing new Brainfuck code. Once the execution is finished their state is frozen in time and ready to be viewed.
110 <a id="l101" href="#l101">101</a> 
111 <a id="l102" href="#l102">102</a> # Examples for Debugging:
112 <a id="l103" href="#l103">103</a> Suppose you want to make the tape only 10 bytes long (instead of the default 30000) This way you can easily view the tape contents after execution:
113 <a id="l104" href="#l104">104</a> ```
114 <a id="l105" href="#l105">105</a> &gt; (setf brain:*tape-size-default* 10) ;Sets the tape to only elements 0 to 9
115 <a id="l106" href="#l106">106</a> &gt; #f-&gt;+ ;Sets cell to 255, shifts right and sets to 1
116 <a id="l107" href="#l107">107</a> &gt; brain:*tape* ;Holds the byte tape vector
117 <a id="l108" href="#l108">108</a> #(0 0 0 0 0 255 1 0 0 0)
118 <a id="l109" href="#l109">109</a> &gt; brain:*pointer*
119 <a id="l110" href="#l110">110</a> 6
120 <a id="l111" href="#l111">111</a> &gt; (byte-value)
121 <a id="l112" href="#l112">112</a> 1
122 <a id="l113" href="#l113">113</a> ```
123 <a id="l114" href="#l114">114</a> Suppose you want to find information about the execution of `incf-byte` and `decf-byte`:
124 <a id="l115" href="#l115">115</a> ```
125 <a id="l116" href="#l116">116</a> &gt; (trace brain:incf-byte brain:decf-byte)
126 <a id="l117" href="#l117">117</a> &gt; (brain:fuck &quot;+-&quot;)
127 <a id="l118" href="#l118">118</a> ;;;; The following text is implementation dependent, and looks exactly like this only on SBCL
128 <a id="l119" href="#l119">119</a>   0: (INCF-BYTE)
129 <a id="l120" href="#l120">120</a>   0: INCF-BYTE returned 1
130 <a id="l121" href="#l121">121</a>   0: (DECF-BYTE)
131 <a id="l122" href="#l122">122</a>   0: DECF-BYTE returned 0
132 <a id="l123" href="#l123">123</a> &quot;&quot;
133 <a id="l124" href="#l124">124</a> ```
