64 <a id="l55" href="#l55">55</a> ## Accessibility API declaration
65 <a id="l56" href="#l56">56</a> 
66 <a id="l57" href="#l57">57</a> Play asks this of any app whose manifest declares an accessibility service.
67 <a id="l58" href="#l58">58</a> 
68 <a id="l59" href="#l59">59</a> **Is your app an accessibility tool (built to support people with
69 <a id="l60" href="#l60">60</a> disabilities)?** No. The manifest does not set `isAccessibilityTool`.
70 <a id="l61" href="#l61">61</a> 
71 <a id="l62" href="#l62">62</a> **What core functionality uses the AccessibilityService API?**
72 <a id="l63" href="#l63">63</a> 
73 <a id="l64" href="#l64">64</a> ```
74 <a id="l65" href="#l65">65</a> AssistKey is a hardware key remapper for the Viwoods AiPaper Reader, an e-ink reading device. Remapping hardware keys is the app&#x27;s only function, and the AccessibilityService API is the only public Android API that can do it.
75 <a id="l66" href="#l66">66</a> 
76 <a id="l67" href="#l67">67</a> The service is used for six things:
77 <a id="l68" href="#l68">68</a> 
78 <a id="l69" href="#l69">69</a> 1. Key event filtering (flagRequestFilterKeyEvents / onKeyEvent). The service receives presses of the device&#x27;s AI key and volume keys, recognises the gesture the user configured - single or multiple taps, press-and-hold, or a combination of keys - and consumes the press so that the user&#x27;s chosen action runs instead of the default one.
79 <a id="l70" href="#l70">70</a> 
80 <a id="l71" href="#l71">71</a> 2. Performing the action the user bound to that gesture: performGlobalAction (Back, Home, Recents, notifications, quick settings, lock screen, screenshot), dispatchGesture (a swipe, used to turn pages in reading apps that accept only touch input), and ACTION_SCROLL_FORWARD / ACTION_SCROLL_BACKWARD on the scrollable node of the active window.
81 <a id="l72" href="#l72">72</a> 
82 <a id="l73" href="#l73">73</a> 3. Voice typing, if the user binds that action: the service finds the text field that has input focus and inserts the recognised words at the cursor (ACTION_SET_TEXT, or ACTION_PASTE as the fallback). It never writes into password fields.
83 <a id="l74" href="#l74">74</a> 
84 <a id="l75" href="#l75">75</a> 4. Going back to the app that was in use, on Viwoods readers: the service reads the package name of the window in front from window-state events, keeps the latest one in memory only, and uses it to return from the maker&#x27;s AI screen when the user presses the AI key there.
85 <a id="l76" href="#l76">76</a> 
86 <a id="l77" href="#l77">77</a> 5. An on-screen button, if the user binds one: the service draws a small round button in an accessibility overlay window (TYPE_ACCESSIBILITY_OVERLAY). A tap on it runs the action the user chose. The button exists only while it has an action, and it reads nothing from the screen.
87 <a id="l78" href="#l78">78</a> 
88 <a id="l79" href="#l79">79</a> 6. Ink Recents in place of the recent apps of the system, if the user has installed Ink Recents and left the switch on: from the same window-state events, the service recognises the recent-apps screen of the system by its package and class name, sends Back, and starts Ink Recents. It reads nothing from that screen.
89 <a id="l80" href="#l80">80</a> 
90 <a id="l81" href="#l81">81</a> Window content is retrieved only in cases 2 and 3: to locate a scrollable node at the moment the user presses a key bound to the Scroll action, and to read the one focused text field at the moment recognised words are inserted into it. No window content, text, or key event is stored, logged or transmitted. The app does not request the INTERNET permission and cannot transmit anything.
91 <a id="l82" href="#l82">82</a> 
92 <a id="l83" href="#l83">83</a> Before the user is sent to the accessibility settings, the app shows a prominent in-app disclosure describing exactly this use, and proceeds only if the user taps Agree.
93 <a id="l84" href="#l84">84</a> ```
94 <a id="l85" href="#l85">85</a> 
95 <a id="l86" href="#l86">86</a> **Disclosure evidence.** If the form asks for a video: on the main screen tick
96 <a id="l87" href="#l87">87</a> *Accessibility key filter*. The disclosure dialog appears before anything else,
97 <a id="l88" href="#l88">88</a> and only *Agree* continues to Android&#x27;s settings. Record that on any phone
98 <a id="l89" href="#l89">89</a> pointed at the reader - the reader cannot capture its own screen.

100 <a id="l91" href="#l91">91</a> ## Permissions a reviewer may ask about
101 <a id="l92" href="#l92">92</a> 
102 <a id="l93" href="#l93">93</a> | Permission | Why |
103 <a id="l94" href="#l94">94</a> |---|---|
104 <a id="l95" href="#l95">95</a> | `BIND_ACCESSIBILITY_SERVICE` | Above. |
105 <a id="l96" href="#l96">96</a> | `WRITE_SECURE_SETTINGS` | Cannot be granted to a Play install; it does nothing unless the owner grants it over adb. It then lets the app switch the firmware&#x27;s power-button behaviour (short press, hold duration). Declared so that the grant is possible at all. |
106 <a id="l97" href="#l97">97</a> | `RECORD_AUDIO` | Voice typing only. Requested at run time from the Voice typing screen. The speech recognition app the user chose records the audio; Android requires the calling app to hold the permission too. AssistKey receives text only, and stores and sends nothing. |
107 <a id="l98" href="#l98">98</a> | `QUICK_ACCESS_WALLET` | Required of any app offered as the wallet app. AssistKey serves an empty card list; it exists so a press of the wallet shortcut reaches the user&#x27;s chosen action. |
108 <a id="l99" href="#l99">99</a> | `com.android.vending.BILLING` | Play Billing. |
