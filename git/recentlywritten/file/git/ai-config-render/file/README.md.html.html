10 <p>README.md (2777 bytes)</p><pre class="src"><a id="l1" href="#l1">1</a> # ai-config-render (`aicr`)
11 <a id="l2" href="#l2">2</a> 
12 <a id="l3" href="#l3">3</a> Write your AI-agent rules, skills, and MCP servers once. `aicr` renders them into the native files of Claude Code, Codex, Copilot CLI, Gemini CLI, Antigravity, Cursor, Windsurf, or any agent you describe in five lines of TOML.
13 <a id="l4" href="#l4">4</a> 
14 <a id="l5" href="#l5">5</a> It never takes over a file. It owns only:
15 <a id="l6" href="#l6">6</a> 
16 <a id="l7" href="#l7">7</a> - **Instruction files:** the blocks between `&lt;!-- aicr:NAME --&gt;` and `&lt;!-- /aicr:NAME --&gt;`. Your own text stays.
17 <a id="l8" href="#l8">8</a> - **MCP configs:** the server entries it wrote. Your other servers and settings stay.
18 <a id="l9" href="#l9">9</a> - **Skills and plain files:** the paths it wrote last run (tracked in a state file).
19 <a id="l10" href="#l10">10</a> 
20 <a id="l11" href="#l11">11</a> It backs up every file before it changes it (`&lt;file&gt;.aicr-bak-&lt;timestamp&gt;`). Python 3.11+ standard library only.
21 <a id="l12" href="#l12">12</a> 
22 <a id="l13" href="#l13">13</a> ## Quickstart
23 <a id="l14" href="#l14">14</a> 
24 <a id="l15" href="#l15">15</a> ```bash
25 <a id="l16" href="#l16">16</a> pipx install git+https://github.com/equwal/ai-config-render
26 <a id="l17" href="#l17">17</a> aicr list-targets --source examples/basic   # built-in targets; * = enabled
27 <a id="l18" href="#l18">18</a> aicr diff   --source examples/basic         # dry run: unified diff of every change
28 <a id="l19" href="#l19">19</a> aicr render --source examples/basic         # write, with backups
29 <a id="l20" href="#l20">20</a> aicr check  --source examples/basic         # exit 1 if any target drifted (CI, cron)
30 <a id="l21" href="#l21">21</a> ```
31 <a id="l22" href="#l22">22</a> 
32 <a id="l23" href="#l23">23</a> ## Source layout
33 <a id="l24" href="#l24">24</a> 
34 <a id="l25" href="#l25">25</a> Any folder works, git or not:
35 <a id="l26" href="#l26">26</a> 
36 <a id="l27" href="#l27">27</a> ```
37 <a id="l28" href="#l28">28</a> aicr.toml            targets, rules, MCP servers, skills, files, vars
38 <a id="l29" href="#l29">29</a> rules/&lt;name&gt;.md      one block per rule; rules/&lt;name&gt;.&lt;target&gt;.md overrides for one target
39 <a id="l30" href="#l30">30</a> skills/&lt;name&gt;/       copied whole into each target&#x27;s skills folders
40 <a id="l31" href="#l31">31</a> ```
41 <a id="l32" href="#l32">32</a> 
42 <a id="l33" href="#l33">33</a> See [`examples/basic/aicr.toml`](examples/basic/aicr.toml). Enable a built-in target with `[targets.claude]`; override any field, or define a new target:
43 <a id="l34" href="#l34">34</a> 
44 <a id="l35" href="#l35">35</a> ```toml
45 <a id="l36" href="#l36">36</a> [targets.myagent]
46 <a id="l37" href="#l37">37</a> instructions = &quot;${home}/.myagent/RULES.md&quot;
47 <a id="l38" href="#l38">38</a> skills = [&quot;${home}/.myagent/skills&quot;]
48 <a id="l39" href="#l39">39</a> mcp = { format = &quot;json&quot;, path = &quot;${home}/.myagent/mcp.json&quot;, key = &quot;servers&quot; }  # or format = &quot;toml&quot;
49 <a id="l40" href="#l40">40</a> ```
50 <a id="l41" href="#l41">41</a> 
51 <a id="l42" href="#l42">42</a> Any rule, server, skill, or file takes `targets = [...]` and `machines = [...]` filters.
52 <a id="l43" href="#l43">43</a> 
53 <a id="l44" href="#l44">44</a> ## Per-machine values
54 <a id="l45" href="#l45">45</a> 
55 <a id="l46" href="#l46">46</a> `~/.config/aicr/machine.toml` (or `--machine FILE`) holds what differs per computer: `name`, `[vars]`, `skip_targets`, `state`, and `[mcp.&lt;server&gt;]` overrides. `${var}` works in every path and string. Built-in vars: `home`, `home_posix`, `os`, `machine`. See [`examples/machine.example.toml`](examples/machine.example.toml).
56 <a id="l47" href="#l47">47</a> 
57 <a id="l48" href="#l48">48</a> ## Why not ruler, rulesync, or chezmoi?
58 <a id="l49" href="#l49">49</a> 
59 <a id="l50" href="#l50">50</a> - **ruler / rulesync** generate project-level agent files and mostly overwrite them. `aicr` targets user-level config, edits only its own blocks and entries, and backs up first, so it can share a file with your hand edits and with other tools.
60 <a id="l51" href="#l51">51</a> - **chezmoi** manages whole dotfiles. A single `~/.claude.json` mixes your MCP servers with app state that changes every minute; `aicr` merges one key instead of owning the file.
61 <a id="l52" href="#l52">52</a>
