-<p>Using OpenRC runlevels to have lots of instances of simple (network)
-programs like quark for multiple http serving locally or
-<a href="https://tools.suckless.org/ii/" class="external-link">ii</a>
-(or
-<a href="https://tools.suckless.org/sic/" class="external-link">sic</a>)
-for IRC server connections.</p>
-<p>To keep programs simple, they should not do the same process for
-unrelated uses. It is much more complicated to configure and manage
-multiple webservers in the same process (like how nginx does it) than
-just one. Init systems are designed to manage processes, and should be
-used instead. Do one thing etc. etc.</p>
-<p>This is how to use the OpenRC runlevels for quark and ii runlevels as
-examples.</p>
-<h3 id="the-tree-on-my-machine">The Tree (on my machine)</h3>
-<pre><code>/etc/runlevels
-├── boot
-│   └── ...
-├── default
-│   └── ...
-├── irc-base
-│   ├── oftc -&gt; /etc/init.d/oftc
-│   ├── liberachat -&gt; /etc/init.d/liberachat
-│   └── ...
-├── net-base
-│   ├── default -&gt; ../default
-│   └── quark -&gt; ../quark
-├── net-offline
-│   ├── default -&gt; ../default
-│   └── net-base -&gt; ../net-base
-├── net-dns
-│   ├── dnscrypt-proxy -&gt; /etc/init.d/dnscrypt-proxy
-│   └── unbound -&gt; /etc/init.d/unbound
-├── net-wifi
-│   ├── dhcpcd -&gt; /etc/init.d/dhcpcd
-│   ├── net-base -&gt; /etc/runlevels/net-base
-│   ├── net-dns -&gt; /etc/runlevels/net-dns
-│   └── wpa_supplicant -&gt; /etc/init.d/wpa_supplicant
-├── net-wifi-irc
-│   ├── irc-base -&gt; ../irc-base
-│   └── net-wifi -&gt; ../net-wifi
-├── quark
-│   ├── quark-docs -&gt; /etc/init.d/quark-docs
-│   ├── quark-equwal -&gt; /etc/init.d/quark-equwal
-│   └── ...
-├── shutdown
-│   └── ...
-└── sysinit
-    └── ...</code></pre>
-<p>as you can see, IRC is connected after the real internet on wifi
-(net-wifi), but quark runs on any network runlevel using net-base.</p>
-<h3 id="how-to">How To:</h3>
-<p>OpenRC has its own commands for making the runlevels, but I find them
-confusing. Let’s just edit the files.</p>
-<pre><code># make runlevel
-mkdir /etc/runlevels/quark
-# add services (as many as needed)
-ln -s /etc/int.d/quark-whatever /etc/runlevels/quark
-# add runlevel to parent
-ln -s /etc/runlevels/default /etc/runlevels/quark
-# Reload since openrc is in default
-openrc default</code></pre>
-<p>That works, but what about for networked IRC on a custom networking
-runlevel? Just add it to the networking runlevel.</p>
-<pre><code># (first, make a network runlevel that contains default! Without default the system will crash, obviously.)
-mkdir /etc/runlevels/net-wifi
-ln -s /etc/runlevels/net-wifi /etc/runlevels/default
-ln -s /etc/init.d/wpa_supplicant /etc/runlevels/net-wifi
-# etc.
-# Now add the irc-base to the network runlevel
-mkdir /etc/runlevels/irc-base
-ln -s /etc/init.d/liberachat irc-base
-ln -s /etc/init.d/oftc irc-base
-ln -s /etc/runlevels/irc-base /etc/runlevels/net-wifi
-openrc net-wifi</code></pre>
-<h3 id="tool-restart-runlevel">Tool: restart-runlevel</h3>
-<p>Openrc wants switch the whole stack <code>openrc runlevel</code> so I
-made a little tool to just restart a specific runlevel. Nice for
-debugging.</p>
-<pre><code>#!/bin/bash
-
-for link in /etc/runlevels/${1}/*
-do [[ -L &quot;$link&quot; &amp;&amp; &quot;$(readlink &quot;$link&quot;)&quot; == /etc/init.d/* ]] &amp;&amp; \
-    rc-service &quot;$(basename &quot;$link&quot;)&quot; restart
-done</code></pre>
